# ‏`thickness_Module_V3.py` — מדריך מפורט לקוד

קובץ זה מסביר את כל החלקים של המודול ‏`thickness_Module_V3.py`. המטרה: שכל מי שייגש לקוד הזה יוכל להבין במהירות מה כל חלק עושה, איך הנתונים זורמים, ומה תפקיד כל מחלקה/פונקציה.

## תוכן המודול בקצרה

המודול אחראי על:

1. קליטת חבילות UDP משני חיישני מרחק (TOP ו-BOTTOM) ברשת.
2. חישוב עובי החלק לפי הנוסחה ‏`Distance - (TOP + BOTTOM)` דגימה אחר דגימה.
3. זיהוי תחילה וסוף של חלק במדידה (‏`object_in_measurement`‏).
4. סינון, חיתוך וצימצום הדגימות לפרופיל סופי.
5. חישוב סטטיסטיקות לפסילה/אישור: ממוצע, ‏P2P, קוניות.
6. רינדור חזותי של פאנל מדידה (PIL בלבד) — ה-UI החיצוני מקבל רק תמונה.

## 1. ייבואים (שורות 1–16)

- ‏`socket / struct / threading / time / queue` — תקשורת רשת ומקבילות.
- ‏`collections.deque` — מבני נתונים בגודל מוגבל לדגימות אחרונות.
- ‏`numpy` — חישובים נומריים (ממוצעים, ‏`interp`‏ וכו').
- ‏`json / os / pathlib.Path` — טעינה ושמירה של קובץ הקונפיג.
- ‏`PIL (Image, ImageDraw, ImageFont)` — רינדור התמונה הסופית.
- ‏`re` — ביטויים רגולריים לתמיכה ב-RTL/עברית.
- ‏`matplotlib` עם backend בשם ‏`Agg` — רינדור גרף הפרופיל ללא צורך בתצוגה חיה.

ה-backend ‏`Agg` נבחר בכוונה: הוא רץ ב-headless mode (ללא מסך), מתאים לסביבות שרת או embedded, ומאפשר ייצוא ישיר ל-PIL.

## 4. עזרי RTL לעברית — ‏`_rtl_visual` (שורות 64–100)

‏`PIL` לא מבצע ‏BiDi אוטומטי, אז עברית מופיעה הפוך. הפונקציה ‏`_rtl_visual` מבצעת "היפוך ויזואלי":

1. הופכת את כל המחרוזת (‏`s[::-1]`‏).
2. מחליפה כיוון של סוגריים (הם נשארים אסימטריים אחרי היפוך).
3. הופכת בחזרה רצפי ספרות (מספרים נכתבים LTR גם בעברית).
4. הופכת בחזרה רצפים לטיניים (כמו ‏`mm`‏, ‏`PLC`‏) כך שיישארו קריאים.

הפונקציה רצה רק אם המחרוזת מכילה תווי עברית; אחרת מחזירה את הטקסט כמו שהוא, ללא נזק.

## 5. ‏`parse_push_packet` (שורות 110–120)

מקבלת ‏`bytes` שמגיעות בחבילת ‏UDP מחיישן ‏OD5000 (לפי ‏`Table 47`‏ במדריך SICK).

מבנה החבילה:

| ‏Byte | אורך | תוכן |
|-------|------|------|
| 0–1   | 2    | ‏`0xD`‏ + אורך frame |
| 2–5   | 4    | ‏Sensor status |
| 6–9   | 4    | **‏Timestamp** של הערך הראשון, ‏`uint32 BE`‏ ב-`ns`‏, מתאפס כל שנייה |
| 10–13 | 4    | ‏Measurement counter |
| 14+   | משתנה | ערכי המדידה — ‏`int32 BE`‏ בננומטרים |

הפונקציה:

1. בודקת אורך מינימלי (‏`≥18`‏ בתים).
2. שולפת את ‏`ts_ns_first`‏ מבתים 6–9 (**חדש** — היה נזרק בעבר).
3. גוזרת את ה-payload מ-`data[14:]`‏.
4. בודקת שה-payload מתחלק ב-4 (כל ערך תופס 4 בתים).
5. מבצעת ‏unpacking של כל הערכים כ-`int32 big-endian`‏.
6. ממירה ננומטרים למילימטרים (חלוקה ב-1,000,000).

מחזירה ‏`tuple`‏ של ‏`(ts_ns_first, [mm, mm, ...])`‏, או ‏`None`‏ אם החבילה פגומה.

> שדות ‏`Sensor status`‏ ו-‏`Measurement counter`‏ עדיין לא מחולצים. אפשר להוסיף בעתיד לזיהוי ‏`packet loss`‏ או שגיאות חומרה.

## 6. ‏`ThicknessConfig` (שורות 123–202)

מחלקה שטוענת ושומרת את כל הפרמטרים הקבועים מקובץ ‏JSON. הקובץ ממוקם ב-‏`config/config457_thk.json` (יחסית למיקום הסקריפט).

עקרון מנחה: **אין ברירות מחדל בקוד**. אם חסר מפתח בקובץ — נזרקת ‏`KeyError`‏. זה מבטיח שכל deploy עובד עם פרמטרים מפורשים, לא עם ברירות מחדל סמויות.

החריגים: ‏`conicity_thresh_um`‏ עם ברירת מחדל 5.0, וכן ‏`end_of_part_gap_count`‏ שנופל ל-`MAX_ERROR_COUNT`‏ אם חסר (תאימות לאחור).

- ‏`save()` — שמירה חזרה לדיסק (indented).

### מפתחות הקונפיג ומשמעותם

| מפתח                            | משמעות                                                                 |
|---------------------------------|------------------------------------------------------------------------|
| ‏`sensors`                       | מילון של חיישנים, כל אחד עם ‏`port`                                    |

## 7. ‏`ThicknessRuntimeState` (שורות 205–245)

מחזיק את כל המצב הדינמי של ה-runtime. שיתוף בין ת'רדים מחייב ‏`lock`‏.

### שדות עיקריים

- ‏`lock` — ‏`threading.Lock`‏ לכל הגישות הקריטיות.
- ‏`stop_event` — סיגנל ליציאה נקייה מכל הת'רדים.
- ‏`samples` — שני ‏`deque`‏ים (TOP ו-BOTTOM) של ‏`(time, mm)`‏. ‏`maxlen=10000`‏ מבטיח שלא נפוצץ זיכרון.
- ‏`last_ts` — חותמת זמן אחרונה לכל חיישן (שעון וירטואלי).
- ‏`object_in_measurement` — האם כרגע בתוך מדידת חלק.
- ‏`valid_measurement_detected` — האם הייתה לפחות דגימה תקינה אחת בחלק.
- ‏`start_time` — זמן תחילת החלק הנוכחי.
- ‏`sample_count` — כמה דגימות תקינות נצברו בחלק הנוכחי.
- ‏`error_count` — רצף שגיאות נוכחי (אפס בכל דגימה תקינה).
- ‏`timestamps_list` — זמנים יחסיים של דגימות החלק הנוכחי.
- ‏`thickness_values` — ערכי העובי של דגימות החלק הנוכחי.
- ‏`passes` — רשימת חלקים שהסתיימו (היסטוריה).
- ‏`ui_queue` — תור (עד 50 פריטים) לאירועי ‏UI: ‏`live`‏ / ‏`pass`‏.
- ‏`err_hist_um` — 60 שגיאות אחרונות (לתצוגת ‏bell curve).
- ‏`nominal_lock` + ‏`nominal_thickness_mm`‏ + ‏`tol_um` — נומינלי וטולרנס דינמיים (ניתן לעדכן בזמן ריצה).
- ‏`_last_live_push` — מתי בוצע העדכון החי האחרון (לויסות תדר).

### מתודות

- ‏`reset_pass()` — מאפס את שדות החלק הנוכחי לקראת חלק חדש.
- ‏`snapshot_nominal_tol()` — מחזיר העתק בטוח של נומינלי וטולרנס (תחת ‏`lock`‏ נפרד).

## 9. ‏`SensorReader` (שורות 253–297)

ת'רד נפרד לכל חיישן. אחראי על:

1. פתיחת ‏`socket UDP`‏ על ה-`port`‏ של החיישן.
2. ‏`recvfrom`‏ בלולאה.
3. ‏`parsing`‏ של כל חבילה (‏`parse_push_packet`‏).
4. תיוג זמן חכם של כל דגימה.
5. הוספה ל-`state.samples[name]`‏ תחת ‏`lock`‏.

### תיוג הזמן — שילוב חומרה + ‏anchor של ‏host

מאז עדכון מבוסס ‏OD5000 spec, חותמת הזמן של הדגימה הראשונה בכל ‏packet מגיעה מהחומרה (`ts_ns_first`‏ בבתים 6–9, ‏`uint32 BE`‏, ns). המונה מתאפס כל שנייה, אז הקוד עוטף אותו במנגנון:

- בקבלת ‏packet ראשון: ‏`_ts_anchor = time.time() - ts_ns_first/1e9`‏.
- בכל ‏packet עוקב: זיהוי wrap (אם ‏`ts_ns`‏ נפל לאחור ביותר מ-‏`0.5s`‏ — עברה שנייה, ‏`_ts_wraps += 1`‏).
- זמן ה-sample הראשון: ‏`t_first = _ts_anchor + _ts_wraps + ts_ns_first/1e9`‏.
- דגימות עוקבות באותו ‏packet: ‏`t_i = t_first + i * (FRAME_INTERVAL_SEC / N)`‏ (החומרה נותנת חותמת רק לראשונה).

יתרון: דיוק ברמת ‏ns בתוך כל חיישן, ללא drift מהשעון של ה-CPU. הסנכרון בין ‏TOP ל-‏BOTTOM משתפר משמעותית כל עוד שני החיישנים מסונכרנים פיזית (למשל ‏PTP — נתמך ב-OD5000).

הלולאה הפנימית רצה ברציפות עד ‏`socket.timeout`‏, ואז ישנה 0.5ms כדי לא לחנוק את ה-CPU.

## 10. ‏`ThicknessProcessor` (שורות 299–495)

הת'רד שמבצע את כל עיבוד הנתונים. רץ במקביל ל-readers.

### 10.1 ‏`run()` — הלולאה הראשית (שורות 311–368)

בכל איטרציה:

1. מנסה למשוך זוג דגימות (TOP ו-BOTTOM) מסונכרנות בזמן.
   - בודק את הראשונות בכל ‏`deque`‏.
   - אם ‏`dt`‏ ביניהן ‏`≤ TIME_SYNC_THRESHOLD` — ‏`popleft`‏ משתיהן.
   - אחרת — זורק את הישנה יותר, מנסה שוב.
2. בודק "אין אובייקט" (שני החיישנים מעל ‏`ERROR_THRESHOLD_MM`‏):
   - מגדיל את ‏`error_count`‏.
   - אם ‏`object_in_measurement`‏ וגם ‏`error_count ≥ END_OF_PART_GAP_COUNT`‏ (**חדש ב-V3**) — סוגר את ה-pass (‏`process_end_of_measurement`‏).
   - אחרת ממשיך (תעלה או קדח קצר נספרים אך לא סוגרים pass).
3. אם זו דגימה תקינה — מאפס ‏`error_count`‏ ומחשב ‏`thickness`‏.
4. אם ‏`thickness`‏ בתוך החלון ‏`[min, max]`‏ — מצרף לחלק הנוכחי.
5. כל ‏`1/LIVE_UPDATE_HZ`‏ שניות — שולח עדכון "live" ל-`ui_queue`‏.

### 10.2 ‏`process_end_of_measurement()` — סיום חלק (שורות 370–495)

מבוצע פעם אחת לכל חלק שמסתיים. השלבים:

**שלב A — חיתוך קצוות (trim):**
‏`i_lo = m * TRIM_LO` ו-`i_hi = m * TRIM_HI`‏. מוריד טרנזיינטים בכניסה וביציאה של החלק לפני החיישן.

**שלב B — שמירת ‏`raw`‏ לאחר חיתוך (‏`raw_t`‏, ‏`raw_y`‏):**
לתצוגה גרפית מפורטת אם נדרש. נמדד גם ‏`raw_trim_rate_hz`‏ (כמה דגימות לשנייה בפועל אחרי חיתוך).

**שלב C — צמצום ל-`TARGET_POINTS`‏ (downsample):**
חלוקה ל-N segments שווים וממוצע לכל אחד. מתקבלים ‏`avg_t`‏ ו-`avg_y`‏ מצומצמים (בדרך כלל ‏`~100`‏ נקודות).

**שלב D — סטטיסטיקות:**

- ‏`mean_thickness` — ממוצע ‏`y_trim`‏ ב-mm.
- ‏`mean_err_um = (mean - nominal) * 1000`‏.
- ‏`p2p_um = max - min`‏ של ‏`avg_y`‏ ב-µm.
- ‏`conicity` — ממוצע 3 נקודות ראשונות פחות 3 אחרונות. ערכים: ‏`conicity_delta_mm`‏, ‏`conicity_signed_um`‏ (עם סימן ±), ‏`conicity_um`‏ (ערך מוחלט). קוניות שלילית = החלק עבה יותר בקצה הראשון.

**שלב E — קביעת תקין/פסול:**

- ‏`ok_nominal = |mean_err_um| ≤ tol_used_um`‏
- ‏`ok_p2p     = p2p_um ≤ P2P_THRESH_UM`‏
- ‏`ok_conicity = |conicity_signed_um| ≤ CONICITY_THRESH_UM`‏
- ‏`status = "תקין"`‏ אם ‏`ok_nominal AND ok_conicity`‏, אחרת "פסול". **כרגע ‏`ok_p2p`‏ לא משפיע על הסטטוס הראשי** — ראה הערה למטה.

**שלב F — סיבת פסילה (‏`fail_reason`‏):**
מחושבת לתצוגה. עדיפות:

1. סטייה מהנומינלי — "גבוה/נמוך מהנומינלי".
2. קוניות מעל הסף — "קוניות גבוהה".

**שלב G — בניית ‏`dict`‏ של ה-pass והוספה ל-`state.passes`‏.**
כולל גם ‏`raw_samples`‏, ‏`duration`‏, ‏`raw_trim_count`‏ וכו'.

**שלב H — עדכון histogram:**
‏`err_hist_um.append(mean_err_um)`‏ (‏`deque`‏ עם ‏`maxlen=60`‏).

**שלב I — שליחת אירוע ‏`"pass"`‏ ל-`ui_queue`‏.**

**שלב J — ‏`reset_pass()`‏ לקראת החלק הבא.**

> הערה לגבי ‏`ok_p2p`‏: כרגע הוא מחושב אך אינו משפיע על ‏`status`‏ או ‏`fail_reason`‏ הסופיים. אם תרצה ש-‏`P2P`‏ יוכל לפסול חלק — צריך להוסיף אותו לתנאי ה-`status`‏ ול-`fail_reason`‏.

## 11. ‏`ThicknessModule` — ה-API הציבורי (שורות 500–543)

עטיפה נוחה שמרכיבה את כל החלקים יחד בלי ‏`UI`‏ מובנה:

- ‏`__init__` — יוצר ‏`state`‏, ‏`readers`‏ (אחד לכל חיישן ב-`Cfg.SENSORS`‏), ו-`processor`‏ אחד. מקבל ‏`get_job_limits`‏ אופציונלי לעקיפת חלון התקין per-job (שימושי תחת ‏`T3`‏).
- ‏`start()` — מתחיל את כל הת'רדים.
- ‏`stop()` — מסמן ‏`stop_event`‏, ממתין שהת'רדים יסיימו (‏`timeout 0.5s`‏), ואם נשארה מדידה פתוחה — מסיים אותה (‏`process_end_of_measurement`‏).

### ‏API חזותי

- ‏`get_display_image(last_n, size_px)` — מחזיר תמונת ‏`PIL`‏ (‏`RGB`‏) של כל הפאנל, מבוסס על ‏`last_n`‏ חלקים אחרונים.
- ‏`get_ui_packet(last_n, size_px)` — מחזיר ‏`tuple`‏ של ‏`(img, mean_mm, p2p_um, conicity_signed_um)`‏ — כל המידע ארוז יחד כדי שה-`UI`‏ יראה תמונה ומספרים מסונכרנים.

## 12. ‏`get_display_payload` (שורות 551–621)

הפונקציה שמרכזת את כל מה שצריך לתצוגה ל-`dict`‏ אחיד. שילוב של מספר חלקים אחרונים (‏`last_n`‏) כדי להציג ממוצע חלקי.

### האלגוריתם

1. אם אין ‏`passes`‏ — מחזיר ‏`payload`‏ "ממתין" עם ערכי ‏`nominal/tol`‏ עכשוויים.
2. ‏`ref = passes[-1]`‏ (משמש כ-anchor לזמנים).
3. ‏`t_common = avg_t`‏ של ‏`ref`‏.
4. לכל ‏`pass`‏: אם זהה ל-`t_common`‏ — מצרף. אחרת — ‏`np.interp`‏ לציר משותף.
5. ‏`y_mean`‏ = ממוצע אנכי של כל ה-passes על ‏`t_common`‏.
6. בניית ‏`dict`‏ עם ‏`profile_t`‏, ‏`profile_th_mm`‏, ‏`mean`‏ ו-‏`err`‏, ‏`p2p`‏, ‏`conicity`‏, ‏`status`‏, ‏`ok flags`‏, ‏`nominal_used`‏, ‏`tol_used_um`‏ וכו'.

> חשוב: שדות המספרים כולם ‏`float()`-ified‏ כדי שיעבדו ב-`JSON serialization`‏. הפונקציה ‏`_safe_float_list`‏ (שורות 545–549) מבטיחה שאם אחד מהפריטים לא ניתן להמרה — תוחזר רשימה ריקה (מונע קריסה ב-edge cases).

## 13. רינדור — שכבת ה-PIL (שורות 624–985)

עיקרון: ה-UI לא רואה את הנתונים — רק תמונה.

### 13.1 ‏`_profile_plot_pil` (שורות 628–660)

רינדור גרף הפרופיל באמצעות ‏`matplotlib`‏ (‏`Agg backend`‏), ואז העברה ל-`PIL`‏. מצייר:

- קו עם ‏`markers`‏ של ‏`profile_t`‏ מול ‏`profile_th_mm`‏.
- קו אופקי על הנומינלי.
- שני קווים מקווקווים על ‏`±tol_mm`‏.
- ‏`ylim`‏ מצומצם ל-‏`±1.5*tol`‏ סביב הנומינלי לקריאות.

אם אין נתונים — טקסט ‏`"Waiting for first part…"`‏.

### 13.2 ‏`_smooth_counts` (שורות 663–681)

החלקת ‏`Gaussian 1D`‏ ידנית (‏`sigma_bins=1.2`‏ כברירת מחדל). משמש להחלקת היסטוגרמת השגיאות לפני שרטוט עקומת הפעמון.

### 13.3 ‏`_gauge_pil` (שורות 684–787)

הציור הקריטי. בנוי משלושה חלקים על קנבס יחיד:

- **למעלה**: עקומת פעמון (bell curve) מעל ההיסטוגרמה של ‏`err_hist_um`‏.
- **באמצע**: בר צבעוני — אדום | צהוב | ירוק | צהוב | אדום.
- **למטה**: ‏`ticks`‏ ותוויות µm. מצביע (חץ עם ידית) מציג את ‏`mean_err_um`‏ הנוכחי על הסקאלה.

### הפרמטרים העיקריים

- ‏`total_um=20` — טווח מלא ‏`±10µm`‏.
- ‏`green_half_um=3` — אזור ירוק = ‏`±3µm`‏.
- ‏`yellow_um=1` — אזור צהוב = רוחב ‏`1µm`‏ משני הצדדים של הירוק.
- ‏`tick_um=1` — מרווח ‏`tick`‏.

### 13.4 ‏`_compute_big_status_lines` (שורות 790–845)

מחשב את הטקסט והצבע לשורת הסטטוס הגדולה:

- "תקין" — ירוק.
- "פסול":
  - אם סטייה מנומינלי — מציע תיקון "להוריד/להעלות ‏`X mm`‏".
  - אם קוניות — מחשב ‏`dh_mm = (|c|*800)/(1000*span_mm)`‏ ומציע תיקון. (הקבוע ‏`800`‏ שייך לגיאומטריה הספציפית של הסידור — אם תשנה את הסידור הפיזי, ייתכן וצריך לעדכן.)
- מבצע ‏`_rtl_visual`‏ על כל השורות לפני החזרה.

### 13.5 ‏`render_thickness_panel_pil` (שורות 848–984)

הפונקציה הראשית של הרינדור. בונה תמונה בגודל ‏`size_px`‏ (ברירת מחדל ‏`420x900`‏) מלמעלה למטה:

1. 4 ריבועים בראש: מקבילות / קוניות / נומינלי / ממוצע.
   - מקבילות: 👍 אם בתחום הטולרנס, אחרת ↓ או ↑.
   - קוניות: 👍 אם בתחום, אחרת ↻ או ↺ (לפי סימן ‏`conicity_signed_um`‏).
   - לריבועים 0 ו-1 גם אייקון ‏`PNG`‏ מהתיקייה ‏`icons/`‏.
2. שורת סטטוס גדולה (עד שתי שורות, ירוק או אדום).
3. ה-gauge.
4. גרף הפרופיל.
5. שורת סטטוס תחתונה: ‏`status | mean=X mm | Δ=Y µm | cone=Z µm`‏.

חזרת התמונה כ-`PIL.Image RGB`‏.

## 14. סדר זרימת הנתונים (Data Flow)

1. **חיישן TOP** שולח ‏`UDP`‏ → ‏`SensorReader`‏ (ת'רד 1) → ‏`state.samples["TOP"]`‏.
2. **חיישן BOTTOM** שולח ‏`UDP`‏ → ‏`SensorReader`‏ (ת'רד 2) → ‏`state.samples["BOTTOM"]`‏.
3. ‏`ThicknessProcessor.run`‏ (ת'רד 3) שולף זוגות מסונכרנים → מחשב ‏`thickness`‏.
4. דגימות תקינות נכנסות ל-‏`state.timestamps_list`‏ ו-‏`state.thickness_values`‏.
5. בסיום החלק → ‏`process_end_of_measurement`‏ → ‏`pass`‏ חדש ב-`state.passes`‏.
6. ‏`ui_queue`‏ מקבל אירוע ‏`"pass"`‏ (וגם אירועי ‏`"live"`‏ במהלך המדידה).
7. ‏`get_display_payload`‏ → ‏`render_thickness_panel_pil`‏ → ‏`PIL.Image`‏ → ‏UI חיצוני.

## 15. נקודות חשובות לתחזוקה

- כל שינוי במבנה החבילה (‏`parse_push_packet`‏) דורש עדכון של ה-`firmware`‏ של החיישן וגם של הקוד כאן. כרגע ההנחה: ‏`14B header + N*4B int32 BE`‏ בננומטרים.
- שינוי במבנה ה-‏`pass dict`‏ (‏`process_end_of_measurement`‏) משפיע על:
  - ‏`get_display_payload`‏ (שדות שהיא קוראת).
  - שמירה היסטורית (אם תהיה בעתיד — לא ממומשת כרגע).
  - צרכני ‏`ui_queue`‏ בקוד החיצוני.
- הרינדור הוא נקודת תשומת לב ביצועית. בכל קריאה ל-‏`render_thickness_panel_pil`‏ נוצרת ‏`Figure`‏ של ‏`matplotlib`‏ (יקר). אם תדר הרינדור גבוה — שווה ‏`caching`‏.
- ‏`end_of_part_gap_count`‏ (נוסף ב-V3) מאפשר מדידת חלקים עם תעלות/קדחים. ערך גדול = יותר סובלנות לתעלות, אבל גם השהיית סגירה ארוכה יותר בסוף חלק. כלל אצבע: ‏`max_groove_length_mm / part_speed_mm_per_sec * sample_rate_hz`‏.
- בטיחות ת'רדים: כל גישה ל-‏`state.samples / passes / timestamps_list / thickness_values`‏ חייבת להיות תחת ‏`state.lock`‏. ‏`nominal_thickness_mm`‏ ו-‏`tol_um`‏ תחת ‏`nominal_lock`‏ בנפרד, כדי שעדכון נומינלי בזמן ריצה לא יחסום את ה-`processor`‏.
- אין ‏`error logging`‏ מובנה. אם ‏`SensorReader`‏ נופל מחריגה לא-`socket.timeout`‏, הת'רד מת בשקט. מומלץ להוסיף ‏`try/except + logging`‏.
